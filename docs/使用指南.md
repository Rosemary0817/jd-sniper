# 黑五抢购台 · 使用指南

> App 内已内置同一份指南（主界面 →「使用指南」），离线可看。这份文件适合打印或发给别人。

---

## 一分钟理解它在干什么

到点（周四 20:00、周五 10:00 / 16:00 / 20:00 / 22:00）自动帮你：

1. 提前 5 分钟把京东商品页加载好；
2. 整点前 30 毫秒开始点「预约」→「立即抢购」→「去结算」→「提交订单」；
3. 抢到后强震动 + 全屏通知，喊你去付款。

它**不**做的事：不自动付款、不硬过验证码、不刷接口、不保证抢到。

## 第一次用：5 步

### 第 1 步：把 4 项权限点成绿色

| 权限 | 为什么必须 | 不开的后果 |
|---|---|---|
| 精确闹钟 | `setAlarmClock` 需要 | 闹钟被合并到维护窗口，晚几分钟才响 |
| 忽略电池优化 | Doze 会冻结后台 | 到点进程已被冻，什么都不发生 |
| 后台弹出界面 | Android 10+ 后台启动界面要豁免 | 服务活着但界面拉不起来 |
| 通知（含全屏） | 全屏 Intent 靠通知通道 | 锁屏时唤不醒屏幕 |

**国产 ROM 额外开**（系统设置里找）：

- 小米 / Redmi：应用管理 → 本应用 → 自启动打开、省电策略「无限制」、后台弹出界面允许
- 华为 / 荣耀：应用启动管理 → 关自动管理 → 三个开关全开
- OPPO / 一加 / realme：耗电管理 → 允许后台运行、自启动、关联启动
- vivo：后台高耗电 → 允许；自启动 → 允许

### 第 2 步：登录京东

点「登录京东」→ 在打开的页面里扫码或账号登录 → 看到「登录态已就绪」→ 点「已完成登录」返回。

Cookie 存在系统 WebView 里，抢购台复用同一份 `pt_key`，不用登录两次。一般能撑几天到几周。

### 第 3 步：填商品

- 把京东商品链接整条粘进输入框 → 自动解析成纯数字 SKU，并生成 `m.jd.com` 打开地址；
- 别名写中文，抢购台和日志里好认；
- 关掉开关就不参与本次抢购；
- **最多 4 个**（再多内存和 CPU 会拖慢第一次点击）。

推荐顺序：**纸巾 / 可乐优先**。截图里鸡蛋 14 万+人预约，纸巾只有 7000+，同样的手速命中率高一个数量级。

### 第 4 步：保存并布防

点「保存并布防」→ 顶部出现「下次开抢 周五 11月13日 10:00 / 还有 2 天 3 小时」→ 说明闹钟已排好。

> **想临时停掉？** 点顶部那个「布防中」胶囊，变成「已暂停」就立刻取消闹钟，到点不会再自动开抢。商品、时间表、登录态全部保留，再点一次「已暂停」恢复。
>
> 抢购台里的「停止」是另一件事：它只停当前这一轮点击，不影响下一次排期。

### 第 5 步：试跑一次

点「校准时钟」（看到偏差 ms 就对了）→ 点「打开抢购台」→ 观察：

- 每张卡片状态从「准备中」变「已就绪」；
- 底部日志出现 `[sku] ready`；
- 点「诊断当前页」，日志里出现 `PROBE: {"stage":"ITEM","buttons":[...]}`。

确认没问题后点「停止」，回到主界面等着就行。

## 抢购台状态含义

| 状态 | 颜色 | 含义 | 你要做什么 |
|---|---|---|---|
| 准备中 | 灰 | 页面正在加载 | 等 |
| 已就绪 | 绿 | 页面加载完，脚本已注入 | 等 |
| 已布防 | 绿 | 收到开火指令，等到点 | 等 |
| 已预约 | 绿 | 点到了「预约 / 预约Ta」 | 等 |
| 已点抢购 | 橙 | 点到了「立即抢购 / 立即购买」 | 等 |
| 已加购 | 橙 | 点到了「加入购物车」 | 等 |
| 进结算 | 橙 | 在购物车点到了「去结算」 | 等 |
| **订单已提交** | 绿 | 成功，停在收银台 | **立刻去京东付款** |
| 已抢完 | 红 | 页面出现「已抢完 / 无货」 | 等下一个整点 |
| 找不到按钮 | 橙 | 页面结构变了 | 点「诊断当前页」 |
| 需验证 | 黄 | 命中滑块 / 安全验证 | 在展开的页面里手动过验证，再点「手动开火」 |

卡片标题可以点击折叠 / 展开里面的页面。命中验证时卡片会自动展开。

## 时间表

| 时间 | 动作 |
|---|---|
| 周四 20:00 | 先补预约，再抢（预约过才有资格） |
| 周五 10:00 | 抢购 |
| 周五 16:00 | 抢购 |
| 周五 20:00 | 抢购 |
| 周五 22:00 | 抢购 |

**这 5 个时段可以在 App 里直接改**：主界面点「时间表」卡片进入编辑页。

- 点左侧「周五」→ 每点一次往后挪一天（周五→周六→周日→周一…）
- 点时间数字 → 弹系统时间选择器，精确到分钟
- 点「抢购 / 预约 + 抢」→ 切换动作类型
- 底部「+ 添加时段」最多加到 12 个，每行右侧「删除」
- 改完点「保存时间表」，立刻按新表重排闹钟

时区固定 `Asia/Shanghai`，不跟随手机时区。每个点提前 **5 分钟**拉起界面预热，提前 **250ms** 注入，**整点前 30ms** 开始点击；开火后最多尝试 **90 秒**。

到点前 5 分钟别手动杀 App，也别开省电模式。界面会自己亮起来并保持常亮。

## 常见问题

**Q：到点完全没反应？**
先看主界面「运行权限」是不是 4/4。缺一项都可能唤不醒；小米/华为还要额外开自启动。

**Q：界面起来了但一直「等待布防」？**
本轮 90 秒窗口已经过了。点「手动开火」补抢。

**Q：页面白屏？**
网络断了，或系统把 Android System WebView 禁用了（设置 → 应用 → Android System WebView → 启用）。

**Q：一直「找不到按钮」？**
京东改版了。点「诊断当前页」把日志里的 `buttons` 文本发出来，把新文案补进 `autopilot.js` 的 `TXT` 词典后重新构建。

**Q：提示「需要人工过验证」？**
在展开的 WebView 里过掉滑块，然后点「手动开火」续抢。

**Q：提示「登录态失效」？**
回主界面重新登录一次。

**Q：抢到了但没付上款？**
订单会在 15–30 分钟内取消。看到「订单已提交」立刻切到京东付款。

**Q：能不能自动付款？**
不做。自动支付是最强的风控信号（异地、非常规路径、无生物识别），为省 10 秒赌账号不划算。

## 修改节奏（进阶）

`config/app-config.json` 的 `risk` 段：

| 字段 | 默认 | 作用 |
|---|---|---|
| `jitterMinMs` / `jitterMaxMs` | 60 / 260 | 每轮循环的随机间隔 |
| `tapIntervalMs` | 600 | 同一页面两次点击的最小间隔 |
| `maxAttemptsPerItem` | 3 | 同阶段连点超过 3×4 次记 `stalled` 并放慢 |
| `stopOnSoldOut` | true | 见到「已抢完」立即停 |
| `manualCaptcha` | true | 遇验证码暂停等人工 |

改完要重新构建（`config` 在 `preBuild` 阶段复制进 assets）。

## 它不会做什么

- **不自动付款** —— 停在收银台，付款由你本人完成。
- **不硬刚验证码** —— 遇到滑块就暂停等你，过完手动续抢。
- **不刷接口** —— 所有点击都在真实页面里，签名由京东页面自己生成。
- **不保证抢到** —— 库存、账号权重、网络延迟都在影响结果，它只保证「不漏点、不手抖」。

# 使用说明（真机全流程）

## 0. 前置

- Android 8.0（API 26）以上，最好 Android 12+。
- 手机能装非商店 APK（设置里允许「安装未知应用」）。
- 一个能正常登录的京东账号；活动商品**必须先预约**才有资格。

## 1. 装包

产物：`app-debug.apk`（CI Artifacts 或本地 `gradle assembleDebug`）。

安装后桌面图标叫「京东黑五抢购台」。

## 2. 权限（最重要的一步，跳过必踩坑）

打开 App，主页「必开权限」区四个按钮，全部要点成绿色 ✓：

| 权限 | 为什么必须 | 不开的后果 |
|---|---|---|
| 精确闹钟 | `setAlarmClock` 需要 `SCHEDULE_EXACT_ALARM` | 闹钟被系统合并到维护窗口，晚几分钟才响 |
| 忽略电池优化 | Doze 会冻结后台进程 | 到点进程已被冻，什么都不发生 |
| 后台弹出界面 / 悬浮窗 | Android 10+ 后台启动 Activity 需要豁免 | 服务活着但界面拉不起来，只能看到通知 |
| 通知（含全屏） | 全屏 Intent 靠通知通道 | 锁屏时唤不醒屏幕 |

**国产 ROM 额外步骤**（系统设置里手动找，各版本名字不同）：

- 小米 / Redmi：应用设置 → 应用管理 → 本应用 → **自启动**打开、**省电策略**设为「无限制」、**后台弹出界面**允许。
- 华为 / 荣耀：应用启动管理 → 关掉「自动管理」→ 手动管理里三个开关全开。
- OPPO / 一加 / realme：应用管理 → 本应用 → 耗电管理 → 允许后台运行、允许自启动、允许关联启动。
- vivo：后台高耗电 → 允许；自启动 → 允许。

## 3. 登录

1. 主页点「登录京东账号」。
2. 页面会打开 `plogin.m.jd.com`，扫码或账号密码登录。
3. 登录完成后点「我已登录，返回」，看到「登录态已就绪」即成功。

Cookie 存在系统 WebView 的 CookieManager 里，抢购台复用同一份 `pt_key` / `pt_pin`，不需要二次登录。

> 登录态一般能撑几天到几周。如果抢购台提示「登录态失效」，回来重登一次。

## 4. 填商品

活动页四个商品对应的 SKU 需要你自己抓（见 `SKU与活动页获取.md`）。填法：

- **粘链接**：把 `https://item.m.jd.com/product/100012043978.html` 整条粘进「SKU 或商品链接」，光标移开会自动变成 `100012043978`，并补好 URL。
- **粘纯数字**：直接填 SKU。
- **别名**：写「15枚鲜蛋」这种，抢购台标题和日志里好认。

勾选要抢的。建议 **最多 4 个**（`WebViewPool.MAX_VIEWS`），再多内存和 CPU 都会拖慢首次点击。

点「保存配置」。成功会 Toast「已保存，下次 2026-11-12T20:00」，同时主页顶部显示已布防的事件 key、预热时间、开火时间。

## 5. 校时

点「立即校时」：

- 打三个 NTP 源（`ntp.aliyun.com` / `cn.pool.ntp.org` / `time.windows.com`），取中位数。
- 显示「偏差 xxx ms」。正数表示手机慢，负数表示手机快。
- **偏差超过 800ms 就换网络重校**（4G 与 WiFi 的 RTT 差很多，选延迟低的那个）。

校时结果存本地，2 小时内复用；改系统时间/时区会自动清零重校。

## 6. 预热测试（强烈建议每次都做）

点「预热测试（打开抢购台）」：

1. 4 个商品页开始加载，标题显示「准备中」→「已就绪」。
2. 日志里应出现 `[sku] ready`。
3. 顶部时钟 `.SSS` 在跑，`offset` 与主页一致。
4. 点「诊断当前页」，日志里出现 `PROBE: {"url":...,"stage":"ITEM","buttons":[{"text":"立即抢购",...}]}`。
   - 如果 `buttons` 里没有「预约 / 立即抢购 / 加入购物车」→ 页面要么没加载完，要么改版了，把新文案补进词典（见下）。
5. 手动点一次「手动开火」，看日志是否出现 `grabTapped`（说明点到了）。测试完点「停止」。

## 7. 到点前

- **T-5 分钟**：闹钟触发 → 前台服务 → 全屏通知 → 抢购台自动到前台，屏幕常亮。此时页面已经在加载，不需要你做任何事。
- 手机会震一下、通知栏出现「抢购台已布防」。
- **不要手动杀 App，不要锁屏后放进兜里把屏幕朝下**（部分 ROM 会降频）。

如果界面没自动起来（ROM 拦截），从通知栏点「抢购台已布防」也能进，但会晚几秒。

## 8. 开火瞬间

- T0 前 250ms 原生注入 `__LCS.arm(t0, offset)`，JS 自己等到 `t0-30ms` 开始动作。
- 状态流转：`已预约` → `已点抢购` → `进结算` → **`订单已提交`**。
- 命中提交：界面变红、强震动、全屏通知。**立刻切到京东付款**。

## 9. 没抢到怎么办

- 命中「已抢完 / 无货」：该 SKU 自动停，日志 `done reason=soldOut`。等下一个整点，无需操作（闹钟已排好）。
- 90 秒窗口用完：日志 `done reason=timeout`。
- 页面卡住没反应：点「诊断当前页」看结构，必要时「停止」→「手动开火」重来。

## 10. 日志与复盘

主页「查看日志」→ 列出近三天 JSONL。点「导出 CSV」通过系统分享发给自己。

字段含义：

| 字段 | 含义 |
|---|---|
| `type` | `ready` / `armed` / `reserved` / `grabTapped` / `settleTapped` / `orderOk` / `soldOut` / `risk` / `authExpired` / `done` / `paused` / `stalled` |
| `stage` | 页面识别结果：`ITEM` / `CART` / `SETTLE` / `RISK` / `LOGIN` |
| `attempt` | 本次布防累计点击次数 |
| `detail` | 命中的按钮文本 / 失败原因 / 终止词快照 |

复盘看两点：`grabTapped` 的时间戳与 `t0` 差多少（判断链路延迟）；`done reason` 是什么（判断是没货还是没点到）。

## 11. 改按钮词典（页面改版时）

`android/app/src/main/assets/autopilot.js` 顶部：

```js
var TXT = {
  reserve: ['预约', '预约Ta', ...],
  grab:    ['立即抢购', '马上抢购', ...],
  settle:  ['去结算', ...],
  submit:  ['提交订单', ...],
  soldOut: ['已抢完', '无货', ...]
};
```

把「诊断当前页」里看到的真实文案加进对应数组，重新构建即可。文本匹配是「完全相等 > 前缀 > 包含」，越短越容易被误匹配，尽量写完整文案。

## 12. 改节奏

`config/app-config.json` 的 `risk` 段：

| 字段 | 默认 | 作用 |
|---|---|---|
| `jitterMinMs` / `jitterMaxMs` | 60 / 260 | 每轮循环的随机间隔 |
| `tapIntervalMs` | 600 | 同一页面两次点击的最小间隔（防重复跳转把流程打回） |
| `maxAttemptsPerItem` | 3 | 同阶段连续点击超过 3×4 次记一条 `stalled` 并放慢 |
| `stopOnSoldOut` | true | 见到终止词立即停 |
| `manualCaptcha` | true | 遇验证码暂停等人工 |

改完必须重新构建（`config` 是在 `preBuild` 阶段复制进 assets 的）。
